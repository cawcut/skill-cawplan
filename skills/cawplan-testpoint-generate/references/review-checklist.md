# 测试点自查清单（Review Checklist）

> 本清单是测试点生成 Skill 的参考资产，路径 `references/review-checklist.md`（位于 `skills/cawplan-testpoint-generate/references/`，随 Skill 分发、走版本控制）。
> **用途**：测试点初稿在内部生成完成后、呈现给 SQA 之前，AI 切换到「资深测试评审」视角，对照本清单自审，把常见遗漏补进最终结果。
> **只服务「生成后自审」这一步**，不落库、不进 CawPlan。完整执行纪律（一轮、同轮上下文、过薄跳过、增量范围、`is_edited` 等）见 `SKILL.md` §6。

---

## 一、边界（先划清，避免和别处重复）

本清单**只收录「生成时机制兜不住、要靠生成后回头看才发现」的漏点**。凡是 `coverage-dimensions.md` 的变化轴 / 取值级收口在**生成时**已经管的（如状态机反向流转、幂等、边界取值齐全），**不在本清单重复**——那是生成时的事，不是自审的事。

两份清单分工固定，条目不互相搬运：
- `coverage-dimensions.md`：**生成时**发散——该覆盖哪些面。
- 本清单：**生成后**批判——回头查哪些常见坑没填。

---

## 二、三条纪律

1. **自审在内部完成，只呈现最终版**：生成初稿 → 对照本清单补漏 → 只向 SQA 输出自审后的完整结果。**不得先输出初稿、再输出修订版**；SQA 只看到一版。补上的测试点并入正式清单（重新分组、重算序号），与初稿**无差别、不标来源**；补上的疑点并入存疑清单。
2. **审出的漏按红线分流**：方向明确的通用标配 → 补测试点；只是具体值/实现不明 → 补存疑。补充仍受既有红线约束（不编造具体值、不做覆盖矩阵、宁少不宁多、不适用则静默）。
3. **不汇报、不打钩、不标来源**：不向 SQA 说「我自查了哪几条」，不对着清单逐条打钩输出（那是变相覆盖矩阵），不标记哪条是自审补的。清单是内部脚手架，不是输出物。

---

## 三、A 层 · 自审应补上（生成时易漏、机制兜不住的）

逐条对照初稿，命中即补。括号内是给维护者的说明，**AI 自审只需读加粗那句**。

**适用性**：对照每条前，先判断本需求是否涉及该模式（如 #4 需编辑/更新场景、#5 需权限/协作）。**笃定不适用 → 跳过该条，静默**（不生成、不存疑、不汇报）。

1. **默认值：验了「选中态」，也要验「结果生效」。**（常见漏：只生成「默认选中 X」验 UI 态，没生成「用默认值 X 时最终结果正确」。默认值是最高频路径，漏其结果 = 漏最高频路径。）

2. **枚举/挡位的结果验证要列全每一项，尤其别漏默认那项。**（常见漏：结果验证只列部分挡位，把默认值那项当成「默认态已测」而排除，如挡位 5s/10s/15s 只验了 5s/10s 结果、漏了默认的 15s。正解：在**一条测试点标题内列全各挡位取值**（如 `5s/10s/15s，含默认`），不在 A2 按挡位拆多条；逐值可执行用例留给 A3。须遵守 SKILL 颗粒度：列的是**取值清单**，不是**逐值操作步骤**。）

3. **输入字段查「内容形态」，不只「长度」。**（常见漏：只测超长/超限，漏了纯空格绕过必填、特殊字符/脚本注入、emoji/换行/编码。自由文本字段尤其高发。）

4. **编辑/更新类查「空更新」与「部分更新」。**（常见漏：默认都在「改了再存」，漏了不改直接存、只改一个字段时另一字段是否被清空——「改一个字段导致另一字段被置空」是编辑高发 bug。）

5. **权限类查「传递/变更撤销/后端」三件套。**（常见漏且高危：① 权限传递——可编辑者能否再授权、授出的权限能否超过自己；② 变更/撤销的即时性——降权/撤销后是否立即生效，尤其对方正在使用时；③ 后端越权——前端限制是否有后端校验兜底，仅查看权限绕过前端直接调编辑接口拦不拦。凡「前端限制」类测试点须追问「后端是否也校验」。）

6. **「该测什么明确、只是具体值不明」的，别整条丢存疑。**（常见漏：把「错误凭证应失败并提示」这种通用标配，因文案/次数需求没写而整条塞存疑。正解：拆成「通用方向测试点直接生成」+「具体值存疑」并存。与 SKILL closure (a) 互补，专治过度存疑。）

---

## 四、B 层 · 留给人（AI 至多存疑点一句，不假装能补）

以下靠**产品/领域隐性知识**，需求和清单都给不了，AI 无从得知。B 层作**能力边界意识**，运行时**不逐条读入**；遇到相关主题时 **至多在存疑里点一句「建议人工确认」**，不得凭空编造、不得假装已覆盖。列出来是让 AI 知道自己的能力边界、老实交给人，而非要求 AI 补全。

- **配置项之间的联动/互斥**（如「4K 仅付费」「某平台不支持某时长」——组合约束需求常不写）。
- **产品特有隐性规则**（内部约定的上限、禁用词、特定校验）。
- **跨功能的边界归属**（某点该归本功能还是相邻功能）。
- **主观/体验类判断**（画质、美观、流畅度等无法客观断言的点）。

---

## 五、维护

- 只往 A 层加「生成机制兜不住、非生成后回头看不可」的新漏点；凡 coverage-dimensions 的轴能覆盖的，去补那边的追问，不进本清单。
- 规则兜不住、靠隐性知识的，归 B 层，不硬塞进 A 层假装能自动补。
