# 测试用例设计四法(A3 展开参考)

> A3 用途:拿到**一个测试点**,用 EP / BVA / ST / EG 把它铺成用例的**步骤与取值**。
> 分工:A2 用变化轴定"测哪些面",A3 用四法定"每个面**怎么取值、怎么铺步骤**"。四法跑在每个测试点上,不跑在需求上。
> ⚠️ **贯穿全文**:下面示例里的具体数字(6–20 位 / 5 次 / 1000 字符)是讲方法的道具,**不是可照抄进用例的值**。真实用例的任何具体值只能来自测试点标题或五字段;方法只提示"该测边界/该补坑",数值缺失按 §红线0 处理。

---

## 0. 使用姿态(总则)

- **固定顺序当思考轨,不强制跑全**:每个测试点按 `EP → BVA → ST → EG` 过一遍,但该用哪个用哪个;用不上的**静默跳过**,不声明"本条不适用 XX 法"。
- **工具箱,不是清单**:不勾选、不追求"盖满四法"、不标"设计方法"列(CSV 无此列)。
- **只在已有测试点上展开,不发明覆盖面**:某法想到"该测但无对应测试点"的面 → **走存疑**("此面无测试点覆盖,建议回 A2 补一条后刷新重展开"),不自造用例。

---

## 1. EP 等价类划分

给一个输入定"该测哪几类":处理方式相同的算一类、测一个代表;不同的分开各测。A3 特有铺法:

- 一条用例可覆盖多个**有效**类(省用例);每个**无效**类**单独一条**(便于定位,也对应拆合规则"响应不同就拆")。
- 登录例:密码 → 正确(有效)/ 错误(无效)/ 空(无效);"错 1 位"与"全错"同属一类测一个,"错误"与"空"分开。

## 2. BVA 边界值分析

有范围/长度/数量处专戳临界(下限±1、上限±1),中间值不必专测。先 EP 划域,再对边界做 BVA。

⚠️ **红线 0 在此最要命**:边界的**具体数值必须源里真写了**。
- 源写"密码 6–20 位" → 铺 5/6/20/21 位。
- 源**只说**"有长度限制"、没给数 → 写方向性"低于最小长度应被拒绝并提示(具体长度以实现为准)",或转存疑。**不许自己编 6–20**。

## 3. ST 场景法

跟着用户走整条流程:主路(成功路径)/ 岔路(换走法也达成)/ 死胡同(出错处理)。三者常对应用例的 Group 分组。

- 主路至少一条走通;岔路 = 主路 + 分支;死胡同 = 触发点 + 可验证的异常结果。
- ⚠️ 异常流的提示文案 / 回退到哪步 / 锁定多久只能来自源;没写就写方向性,不编。
- 登录例:主路(账号→密码→登录→首页);岔路(记住我 / 验证码登录);死胡同(密码错→提示并停留登录页)。

## 4. EG 错误推测

凭经验挑开发易忘的坑,补前三法覆盖不到处。取值菜单(挑相关的,不逐条勾满):空值/仅空格、特殊字符、超长、注入(SQL/XSS)、emoji;重复提交、并发、操作中断、跳步、回退;首末条、重复/被引用数据、空列表;浏览器/屏幕/弱网/时区。

⚠️ **EG 收口最紧**:只用来给**已有测试点**铺更刁钻的取值/多一步操作。
- 判断口诀:是"给某已有测试点换更刁钻的输入"(→ 铺)?还是"测一个当前没人管的新情形"(→ 存疑,不铺)?
- 红线 0:超长写"超出长度上限的输入"不写"1000 字符";注入写"含脚本/SQL 片段的输入应被转义、不执行不报错",不编具体 payload。

> 数量怎么控(一个测试点铺几条)见 `testcase-writing-spec.md` 的拆合规则,本文件不重复。

---

## ⚠️ 本文件(及据此产出的用例)不得出现

- ❌ 四法做成勾选清单 / 覆盖矩阵(如"须标 ☑EP ☑BVA""每测试点四法齐全")。
- ❌ 数量/比例门禁(如"每测试点≥N 条""P0 占 10–15%""步骤 1–15 步")。
- ❌ 用四法开新覆盖面(尤其 EG);缺面 → 存疑回 A2,不自造孤儿用例。
- ❌ 编造源里没有的具体值(次数/阈值/长度/文案/错误码/payload);示例数字仅用于讲解。
- ❌ 自学习 / 记忆 / 历史缺陷统计(A3 无状态)。
- ❌ "信息缺失就先按合理假设写用例";缺 → 方向占位或存疑。
